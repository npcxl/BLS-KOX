### 调研方式与关键结论（可复用）

- 用 6 个并行 code-explorer 子代理分别覆盖：system 核心 CRUD、配置类页面、日志/安全/webhook、
  文件+租户、AI+运维+首页+个人设置、认证流程。自己读跨领域骨架
  （`app.ts`、`core/crud.ts`、`core/router.ts`、`middleware/*`、`security/rate-limit/*`、
  `security/session/*`、`config/replay-protection.ts`、`shared/utils/redis.ts`、
  `config/dynamic-config.ts`、`api/common/excel`、`security/file-security.ts`）。
- 后端几乎所有业务模块都是**手写 Koa Router**（dept/user/role/menu/config 混合模式/dict/theme/
  page-config/log/security/webhook/storage/tenant/package/ai-model/ai-usage/dashboard），
  只有 config、theme 走 `defineCrudModule`。
- Redis 只在 `bls-server` 使用（`shared/utils/redis.ts`，ioredis keyPrefix `bls:`）。
- 发现一批**文档化的事实性问题**（已在各页面「Known gaps」记录，未改代码）：
  - `sys_security_log` 表结构与 `writeSecurityLog()` 不一致（缺 `log_id`/`source`），前端 `rowKey="logId"`。
  - 登录流程**不写** `sys_login_log`（`writeLoginLog` 从未被调用）→ 登录日志页可能为空，
    且登录爆破的 `LOGIN_FAILED` 安全日志也没写。
  - `POST /api/system/user/reset-password` 只有防重放 signature 规则，**没有路由**。
  - `GET /api/system/storage/file/:fileId/download` 返回 DB 行 JSON 而不是文件流（下载功能坏）。
  - 前端 `system:theme:create` / `system:user:create` 与后端 `:add` 权限码不一致。
  - 日志类接口无 `tenant_id` 过滤。
  - AI 会话接口缺 user/tenant 归属校验（POST 更新分支只按 id、messages GET 无归属）。
  - `/api/ai/chat/conversations` 防重放豁免是精确匹配，PUT 重命名与 messages 子路径仍需 nonce。
  - 租户 `expireTime` 无任何过期校验；`packageId` 无外键校验。
  - 存储 `aliyun_oss/tencent_cos/aws_s3/local` 均为 stub，仅 MinIO 真实实现。

## Koa 主后端 CRUD 完整性修复（本次任务）

范围：`bls-server` 系统管理模块的「列表/详情/新增/编辑/删除/状态 + 校验 + 权限 + 租户隔离 + 软删除 + 字段白名单 + 契约 + 测试」闭环，并同步 SQL/前端/Java/文档。

### 核心：重写 `bls-server/src/core/crud.ts`
- 新增 `applyScope()` 统一构造「租户 + 软删除 + Data Scope」条件，事务内外复用同一套条件
  （修复原来 edit/remove/status 在事务里重建无条件查询导致安全条件丢失）。
- 新增 `GET /:id`；add/edit/remove/status 命中 0 行 → 404；`tenant_id` 只取服务端上下文（fail-closed）。
- 新增字段白名单 `createFields/updateFields/filterFields` 与 `globalTable`；未知字段安全忽略。
- `transactional` 改用 Kysely 原生 `db.transaction()`；`onWrite`/`onTransactionCommitted` 仅在写成功后执行。
- `DELETE /remove` 统一 `{ ids: [] }`（兼容裸数组/逗号串），先校验请求 ID 全部在当前租户可见，否则整体 404。
- `core/router.ts`：修复重复 `wrapCamel(mod.default)` 生成多个包装实例。
- `middleware/permission.ts` + `api/auth`：`hasPerm` 原来读 `user.perms`，而 profile 只返回 `permissions`
  → 非平台租户会 TypeError/500；现已双字段兼容（`perms` 与 `permissions` 同时返回）。

### 各模块
- package：删除写入不存在的 `package_code`/`deleted` 列（原为 SQL 报错）；补 `/status`；菜单分配与删除事务化；
  删除前检查租户引用（409）。
- storage：新增返回 `storageId`；list/detail 脱敏 `access_key/secret_key`；编辑传脱敏值或未传则保留原密钥；
  `is_default` 同租户唯一（事务）；Zod 校验 + JSON 校验。
- page-config：原来**完全无鉴权**；现 `list` 用 `system:pageconfig:list`、`save` 用 `edit`、删除用 `remove`，
  其余读接口需登录；save/delete 全部带 `tenant_id` 并事务化；校验空 pageCode/重复 dataIndex/非法 orderNum。
- dict：type/data 的 list/edit/remove 全部加 `tenant_id` + `deleted`；dictTypeId 归属校验；删类型级联删数据（事务）；
  `/data/type` 需登录，先本租户后回退平台字典，只返回必要字段。
- ai-model：补 `system:ai-model:*` 权限；`GET /:id` 加租户 + 软删除；api_key 统一脱敏且编辑保留原密钥；
  默认模型同租户唯一（事务）；`internal-list` 要求 INTERNAL_SECRET 且支持 tenantId 限定 + 受控字段。
- tenant：list/public-list 过滤 `deleted=0`；public-list 仅返回 tenantId/tenantName/domainName；
  remove 改逻辑删除并禁止删平台租户、有关联用户/角色时 409；`/status` 独立权限 `system:tenant:status`；域名唯一 409。
- user/role/dept/menu：Zod 校验、`deleted=0`、0 行→404、唯一冲突 409（username/roleKey）；用户增删改带 roleIds（事务）；
  删除用户清理 sys_user_role 并吊销会话；删除角色清理 sys_role_menu/sys_user_role；部门删除拒绝孤儿；
  菜单递归删除 + sys_role_menu/sys_package_menu 清理（事务）；修复菜单 add 写 `deleted` 列（表无该列）。
