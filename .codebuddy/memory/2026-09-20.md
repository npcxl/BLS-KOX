## 配置式 CRUD 工厂（defineCrudConfig + fields）

- `bls-server/src/scripts/generate-openapi.ts`：复用 `resolveCrudConfig` 派生文档；尊重 `actions`；请求体字段改为 camelCase。

### 语义要点（后续改代码必须遵守）
- `fields` 是单一字段来源；显式数组（createFields 等）与显式 `schema` **优先**；无 `fields` 的旧配置行为完全不变（selectAll、无自动 Zod）。
- 必填校验在 Zod 对象级用 `superRefine` 实现「snake 或 camel 至少提供一个」，因为请求体两种写法都要支持（早期把两种键都设为 required 会导致 camelCase 请求全部 400）。
- `selectFields` 始终包含主键（否则前端无法 edit/remove）。
- `actions.add/edit` 开启时必须有 create/update 字段，否则启动报错；`actions.status` 开启时必须能解析出 statusField。
- 单测：`src/core/__tests__/crud.test.ts` 86 例（47 旧 + 39 新，覆盖需求 1–22）。
- 顺带修正：`src/config/__tests__/dynamic-config.test.ts` 中两个「源码字符串下标」断言已失效（转译后引号变化导致 `editIdx=-1`，实为空断言），已删除并在 crud.test.ts 用真实行为断言替代。

### 调研结论（重要，后续实现要看）
- **切换模型已经存在，无需改代码**：访问域名 → `sys_tenant.domain_name` → tenant_id →
  该租户 `sys_storage_config` 中 `is_default='1'`（或指定 storageId，或最早创建的）一行 →
  `createStorageProvider()`。所以"按用户/域名切存储"= 每个租户配一行即可。
- **种子行**：`sys_storage_config` `000001` / tenant `000000` / minio / endpoint `minio`
  port 9000 use_ssl 0 / buckets `public-assets`+`private-assets` / `public_base_url='/files'`
  / `is_default=1`。
- **nginx**：`location /files/` 硬编码反代到 `minio:9000/public-assets/`（只服务 MinIO 方案）。
- **公开 URL 已支持 CDN**：`getPublicUrl()` 优先用 `config.publicBaseUrl`，MinIO 与三个 stub
  都实现了；对象 key 是扁平的 `moduleName/uuid.ext`，CDN 回源映射到桶根即可。
- **阻塞点**：`AliyunOssProvider` / `TencentCosProvider` / `AwsS3Provider` / `LocalProvider`
  全是 **stub** —— `upload()` 不发任何网络请求（什么都不落盘）、`remove()` 空实现、
  `getPrivateUrl()` 直接返回公开 URL。只有 `MinioProvider` 真实（putObject / removeObject /
  bucketExists+makeBucket / presignedGetObject 300s）。生产切 OSS 前必须先实现 provider。
- **环境变量不配置应用存储**：`.env.docker.example` 里的 `MINIO_USER`/`MINIO_PASSWORD` 只给
  MinIO 容器用；应用存储配置永远来自 `sys_storage_config`，没有 `STORAGE_*` 引导变量。
- **看着能配但没接线的字段**：`policy_json`（maxSizeMB/allowedExt/privateExpireSeconds）只存不用
  —— 真实大小限制来自 `sys_config.sys.upload.maxSize`，扩展名白名单硬编码在
  `security/file-security.ts`；`private_base_url` 存了但**任何 provider 都不读**；
  `config_json` 存了并传进 StorageConfig，MinIO 不用，留给 SDK provider。

### 本轮新发现的缺陷（已写入各文档的 Known gaps + CHANGELOG）
- **`/openapi/v1` 完全不可用**：全仓没有 `sys_api_key` 表/模型/管理接口 → `openApiAuth`
  永远 `403 Invalid API Key`；`API_KEY_CREATED/REVOKED` 事件常量从未触发。
- **发布中心 WS 推送是死的**：`release.ws.ts` require 路径错误
  （`../../../system/realtime/realtime.ws`）且 `realtime.ws.ts` 从未导出 `getWsServer`；
  `subscribeChannel` 无协议。`release.service.ts` 里的 `sendToChannel()` 全部静默丢弃（页面靠轮询兜底）。
- **realtime 广播未鉴权**：`client.isAuthed` 写了但从没读。
- **`sys_search_index` 字段漂移**：重建写 `create_time/update_time/created_by/source_table`，
  而 Init.sql 只有 `created_at/updated_at`。且 `/search` 用 `LIKE '%kw%'`（FULLTEXT 索引没用上）、
  索引里的 `permission` 字段从不校验、重建全表扫无分批无事务。
- **`sys_jobs` 状态枚举三处不一致**：Init.sql 有 `failed` 无 `dead`；迁移有 `dead` 无 `failed`；
  代码写 `dead`。
- job 的 `export`/`import`/`notification` 是 stub；`system:job:*`、`system:global-search:*`、
  `system:search-index:rebuild` 权限未 seed。
- **`/api/metrics` 无鉴权**（与受保护的 `/internal/metrics` 重复）；`internalAuth`/`openApiAuth`
  比较不是常量时间；IP 白名单是前缀字符串不是 CIDR。
- 前端：17 个未注册脚手架页、`access.ts` 死（两套权限机制）、`global.style.ts` /
  `service-worker.js` / `manifest.json` 死、防重放头生成重复、3 个 raw-fetch AI 客户端
