# 2026-09-23

## Koa 服务依赖自检（启动自检 + 运行期探针 + 巡检）

用户诉求：「KOA 服务运行的时候检查所有微服务，如果没开就要运行时检查出」。

### 结论 / 改动

- 新增唯一注册表 `bls-server/src/observability/service-health.ts`，四个出口复用同一份清单：
  启动报告（`app.ts`，**在 server.listen 之前**）、`GET /api/ready`、`GET /internal/services`、
  `npm run services:check`。
- 注册表：`mysql`/`redis`（core）、`bls-event-service`/`bls-ai-service`（optional，
  `EVENT_SERVICE_URL`/`AI_SERVICE_URL`，开发默认 `http://127.0.0.1:7201`）、
  `bls-captcha-service`（conditional，`TIANAI_BASE_URL`，2xx + JSON 对象）。
- 新 env：`SERVICE_CHECK_STRICT`（生产默认 true → 核心依赖不可用直接 `exit(1)`，不开放端口）、
  `SERVICE_CHECK_TIMEOUT_MS`（5000）、`SERVICE_CHECK_INTERVAL_MS`（60000，0=关闭巡检）。
- 巡检只在下线/恢复的**状态变化**瞬间记日志（不刷屏），定时器 `unref()`，shutdown 时清理。
- 自检输出为框线表格，标题 **`KOX 服务检测`**（用户指定）。列：状态/服务/类别/耗时/地址/检测结果；
  未启动的服务在表下方给出「处理建议」（地址 + 启动命令）。中文表格必须按**显示宽度**（CJK=2 列）
  计算并折行，否则等宽终端里必然错位 —— `displayWidth()` / `wrapByWidth()` / `renderTable()`
  都在 `service-health.ts` 内；测试用「所有框线行显示宽度一致」来守住这一点。
- ⚠ **启动顺序：必须先 `server.listen()` 再自检**。Koa 的实时通道（bls-realtime-ws）与 HTTP
  **共用同一端口**，listen 之前探测必然 `ECONNREFUSED` → 把组件自己误报成「服务未启动」，
  并且巡检会紧接着多报一次「已恢复」（用户实测发现）。现在 app.ts 用 Promise 包 listen
  （监听成功后 `server.off('error', onError)`，之后的服务端错误仍按原行为交给进程），
  然后再 probe + 打印表格 + 严格模式退出。
- 地址列按连通状态着色（连通=绿 `32m` / 不通=红 `31m` / 未配置=灰 `90m`）；**只在真实终端着色**
  （`process.stdout.isTTY`；`NO_COLOR` 关、`FORCE_COLOR=1` 强制），否则日志文件里会混进转义字符。
  `displayWidth()` 必须先剔除 ANSI 序列再算宽度，否则着色后表格会错位。
- 用户明确要求**表格之外不要再打** WARN/ERROR 结构化日志（信息与表格重复，纯噪音）：
  `reportStartupServices` 现在只 `console.log` 这一张表；captcha fail closed 的后果写进了该服务的
  `startHint`（表格里可见），不再单独打 ERROR。
- 用户又要求**去掉汇总行与处理建议段落**：现在 `formatServiceReport()` 只返回表格本身。
  `startHint` 仍留在数据里，通过 `/internal/services` 可取；测试已改为**不依赖标题文字**
  （标题由默认参数决定，用户会自己改），只断言「第一行是带标题的顶边 + 表头 + 无汇总/处理建议」。
- 补齐"其它端口服务"：新增 `bls-realtime-ws`（Koa 自身 `/ws/realtime`，**WebSocket 握手探测**；
  握手阶段不校验 token，认证在首条 `{type:'auth'}` 消息里，所以可安全探测）。
  ⚠ **Java / Rust 是 Koa 的平替方案，不是 Koa 的依赖或联动服务 → 不纳入注册表**（用户明确纠正过一次：
  先前加了 `bls-java-server`/`bls-rust-server` 与新 kind `alternate`/「备用」、env `JAVA_SERVER_URL`/`RUST_SERVER_URL`，
  已全部回滚）。注册表最终固定为 6 项：mysql、redis、bls-realtime-ws、bls-event-service、
  bls-ai-service、bls-captcha-service。
  MinIO 同样不加：Koa 侧没有任何 MinIO 配置来源（只在 ops 页硬编码容器名），且本机 9000 与前端 dev server 冲突。
- ⚠ 协作教训：用户在 IDE 里**实时编辑同一个文件**（标题 `'KOX Healt'` → `'KOX wa'` → `'KOX--Watch'`），
  导致我两次 replace 失败（old_str 里带了那行标题）。**改动 old_str 不要包含用户正在编辑的行**，
  并且测试不要断言会被用户改动的文案。改完要重新读回确认自己的改动还在。
- `/api/ready` 保持向后兼容（`status` + `services`），新增 `degraded`/`summary`/`unavailable`；
  **不返回内网地址**（避免公开端点泄露拓扑），详细视图在需内部鉴权的 `/internal/services`。
- `shared/utils/redis.ts` 增加 `error` 监听器（30s 节流）：ioredis 没有监听器时会静默吞掉连接
  错误 → 「Redis 挂了但日志一片安静」是最危险的一类故障。

### 踩坑（很重要，别再犯）

- **探测超时必须排除"模块编译"耗时**：首次运行 mysql/redis 报 `探测超时（>3000ms）`，
  实际 343ms 就连上了 —— 原因是 `import('kysely')` / `ioredis` 的冷编译落在计时区间内。
  现在每个依赖有 `warmup`（mysql 预热到 `getDb()`，因为它在内部才 `import('kysely')`），
  预热**不**计入探测超时；默认超时也从 3000 提到 5000。
  否则生产 `SERVICE_CHECK_STRICT=true` 会**拒绝启动一个完全健康的实例**。
- 验证 boot 时**不要**用同一个端口起临时实例：会和用户的 `tsx watch` 抢 6001
  （`EADDRINUSE on WebSocketServer`）。用 `APP_PORT=6009` 这类独立端口，并按「启动前后 node
  PID 差集」精确清理，绝不要按名字杀 node。

### 现状（本机实测）

自检能正确报出：`mysql`/`redis` up，`bls-event-service`(7101)/`bls-ai-service`(7201)/
`bls-captcha-service`(8083) 均 `连接被拒绝（服务未启动）`；`/api/ready` → 200 `degraded:true`。

测试：`bls-server` 全量 **657 passed / 39 files**（新增 `service-health.test.ts` 25 项）。

## 前端：`/system/page-config` 左栏改磨砂玻璃选中（UI）

- 文件：`bls-admin/src/pages/system/page-config/index.tsx`（只有这一个文件）。
- 原实现：选中态是**内联样式** + `onMouseEnter/Leave` 直接改 DOM `style.background`；已改为 CSS 类
  `.kox-nav-item` / `.is-active`，hover 交给 CSS。
- 关键点（以后再改这类效果别再踩）：**`backdrop-filter` 在纯色背景上等于没效果** ——
  必须背后有可模糊的底色。所以左栏加了一层极淡的环境光 `.kox-ambient`（三团径向渐变 +
  `blur(10px)` + 16s 缓慢浮动），玻璃质感才看得出来。这一层是我加的，用户没明说，属于实现必需。
- 动效：选中项 `koxNavPop`（translateX+scale 过冲回弹，`.46s cubic-bezier(.34,1.56,.64,1)`）、
  hover `translateX(2px)` 同款弹性缓动；另带 `prefers-reduced-motion` 关闭开关。
- ⚠ 用户明确要求**去掉选中项左侧的蓝色强调条**（`::before` + `koxNavBar` 已删除）。
