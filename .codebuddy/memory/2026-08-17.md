## 重要坑：超管菜单丢失的根因（关键教训）
- 现象：超管 superadmin 登录后 menus 只剩 8 个，大量菜单（角色/菜单/字典/日志中心/安全中心/Webhook/租户/文件中心等）丢失。
- 根因：`000001` 超级管理员角色在 `sys_role_menu` 里的菜单关联**之前就被破坏/丢失**了（只剩按钮 menu_type=2 的 78 条，menu_type 0/1 只剩 8 条）。跟本次加 SQL 审计菜单无关。
- 修复：按 `sql/Init.sql` 中 `000001` 权威清单，用 `INSERT IGNORE` 补全缺失关联（共补到 menu_type 0/1 = 29 条）。
- 教训：`INSERT IGNORE` 遇主键冲突会静默跳过，排查菜单问题必须直接查库核对 `sys_role_menu` 实际数据，不能只看执行 SQL 是否"成功"。

## SQL 审计流程核查（补丁）
- 修复递归 bug：`writeSqlError` 原用 `execute` 落库，`execute` 失败又调 `writeSqlError` → 无限递归。改为直接 `pool.execute` 绕过审计钩子（pool 是 live binding，运行时才访问，无循环依赖）。
- 补 Kysely 路径审计：原 `wrapQueryBuilder` 的 Proxy 只做了重试+指标，没接 SQL 审计，导致 `getDb().selectFrom(...)` 报错的 SQL 不被记录。已在 execute 拦截处 `.catch` 里调 `writeSqlError('kysely', compiled.sql, error)`。
- 关键机制确认：
  - `core/router.ts` 的 `wrapCamel` 全局中间件会把 `ctx.body.data` snake_case 递归转 camelCase（正则 `/_([a-z])/g`），所以 Kysely `selectAll()` 返回蛇形字段，前端用驼峰字段能对上。
  - `middleware/tenant.ts` 的 `tenantMiddleware` 解析 JWT 后调 `setAuthContext`，`writeSqlError` 靠它拿到 userId/tenantId/username。
  - `pool.execute` + `namedPlaceholders:true` 支持 `:name` 命名占位符（项目里 security-audit/event-center 都这么用）。
