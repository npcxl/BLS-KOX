## 用 Docker 启动 BLS-KOX 全栈（Koa 模式）

任务：帮用户用 docker 把服务跑起来。

### 最终状态（全部 healthy）
用 `docker compose --env-file .env.docker --profile ai up -d` 启动，容器：
bls-nginx(8088→80)、bls-admin、bls-server(:7001 Koa)、bls-ai-service(:7201)、

### 踩坑记录（重要，可复用）

**坑 1：profile 服务必须显式带 `--profile` 才会被 `down` 移除。**
无 profile 的 `docker compose down --remove-orphans` 清不掉 `bls-java-server`、
`bls-ai-service`，且报 `Network bls-kox_bls-net Resource is still in use`。
正确清理命令：
```
docker compose --env-file .env.docker --profile ai --profile java --profile event down --remove-orphans
```

**坑 2：Koa / Java 双后端共用硬编码 container_name，切换前必须先 down。**
根因：两个 compose 文件（`docker-compose.yml` 与 `docker-compose.java.yml`）都用
`container_name` 固定命名同一批容器（bls-redis / bls-mysql / bls-minio / bls-nginx…），
且 compose 项目名同为 `bls-kox`。直接用 `-f docker-compose.java.yml up` 叠加启动
必然报 `Conflict. The container name "/bls-redis" is already in use`。
`docker compose ls` 显示的 CONFIG FILES 可用来判断上次跑的是哪套后端。

**坑 3：`bls-ollama-pull` 退出码 1 属预期行为，不影响使用。**
日志 `Error: pull model manifest: file does not exist`。原因是它读 `.env.docker` 的
`AI_MODEL=deepseek-chat`，却拿去 Ollama registry 拉模型，而 deepseek-chat 是云端模型。
AI 服务实际配 `AI_PROVIDER=deepseek` 走云端 API，不依赖本地 Ollama。
如需消除：给 `ollama-pull` 加 `profiles: [local-ai]`，或把 AI_MODEL 改成真实 Ollama 模型
（如 qwen2.5:7b）并同步 AI_BASE_URL=http://ollama:11434/v1。

### 环境提示
用户机器 Docker Desktop 未开机时 `docker` CLI 会报 `npipe:////./pipe/dockerDesktopLinuxEngine`
连接失败。可 Start-Process "C:\Program Files\Docker\Docker\Docker Desktop.exe" 后轮询
`docker info` 等待就绪。当前 Docker Server 版本 29.6.1，Windows + PowerShell。

### 用户偏好
批量强制删除命令（`docker ps -a | ForEach-Object { docker rm -f ... }`）被用户拒绝，
偏好先诊断、给精确命令并征求确认，而不是一刀切强制清理。
