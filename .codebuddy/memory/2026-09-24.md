### 本次梳理出的仓库现状（结论性，后续复用）

- 仓库里其实有**两套互不相通的部署机制**，必须二选一：
  1. **CNB 流水线**（`.cnb.yml` → `.ci/.build.yml`）：push/tag/web_trigger → 构建镜像推
     `docker.cnb.cool` → SSH 到服务器 `DEPLOY_PATH`（默认 `/opt/bls-kox`）→
     `docker-compose -f docker-compose.yml -f docker-compose.deploy.yml --env-file .env.docker pull/up`。
     **这才是「全自动」那条路。**
  2. `deploy-repository-template/`：ghcr.io 镜像 + `docker-compose.prod.yml` + `deploy.sh/rollback.sh`
     的**手工**部署模板（自带版本号 `APP_VERSION`、`http://ip:8088`）。与 CNB 路径完全独立。
- 前端 `bls-admin` 全部走**同源相对路径** `/api/...`（无 baseURL/环境变量），所以
  `admin.xlcig.cn` 一个域名同时提供 SPA + `/api` 即可；`api.xlcig.cn` 只做接口出口。
- **域名→租户只影响登录**：`resolveTenantDomain()`（`shared/utils/domain.ts`，X-Forwarded-Host >
  Host > Origin，仅 `TRUST_PROXY=true` 才信任前者）→ `AuthService.loginByDomain` 按
  `sys_tenant.domain_name`（唯一）匹配；未匹配且非 localhost 直接报「当前域名未绑定租户」，
  **不回退平台租户**。所以：必须把用于登录的域名写进 `sys_tenant.domain_name`，且
  `api.xlcig.cn` 上不能登录（一个租户只能绑一个域名）。
- `extractRequestIp()` 取 `X-Forwarded-For` **第一段** → 双层 nginx 也能拿到真实客户端 IP。
  但容器 nginx 的 `limit_req_zone $binary_remote_addr` 在宿主层反代后会**全部落到宿主机 IP
  同一个桶**里（每 IP 限流退化为全局限流），需要在容器 nginx 配 `real_ip`/`set_real_ip_from`。

### 发现的 6 个阻塞「全自动」的坑（已当面告知用户）

1. `.ci/.build.yml` 的 `<< 'ENDSSH'` **带引号**：`${CNB_DOCKER_REGISTRY_PASSWORD}` /
   `${CNB_TOKEN_USER_NAME}` / `${DEPLOY_PATH}` 在**服务器上**展开 → 变量为空 →
   `docker login` 必然失败（应改为不带引号的 heredoc）。
2. `deploy-config` 任务名叫 sync-config，实际只 `up -d`，**不同步 nginx.conf/compose 文件**。
3. AI/事件服务在 compose 里是 `profiles: [ai]` / `[event]`，流水线不带 profile → 永远不起。
4. **迁移不在流水线里，而且跑不了**：`migrate.ts` 找 `__dirname/../../migrations`，生产镜像
   只 `COPY src → dist`，**没有 `migrations/`** → 会打印 `No migrations dir.` 静默跳过。
   需要在 Dockerfile runtime 阶段 `COPY migrations/ ./migrations/`，部署脚本里加
   `run --rm bls-server node dist/scripts/migrate.js up`。
5. `docker-compose.deploy.yml` 镜像固定 `:latest` → 无法指定版本回滚（建议 `${IMAGE_TAG:-latest}`）。
6. 服务器上的 `.env.docker` 没有来源（gitignore + 流水线不写），必须手工建一次；且
   `.env.docker.example` 里 `${DB_PASSWORD}` 这种**嵌套占位是无效的**（compose 只对 YAML 插值）。

### 给出的推荐架构

- 宿主 nginx 终止 TLS（80/443），4 个 server_name；容器里的 `bls-nginx` 保持 8088，只监听
  127.0.0.1，**8088 对公网关闭**，安全组只开 22/80/443。
- `admin.xlcig.cn` = 管理台（唯一登录入口）+ 同域 /api；`api.xlcig.cn` = 只做接口出口
  （`/api/auth/login`、`/api/captcha/` 直接 403）；`xlcig.cn` / `www.xlcig.cn` 暂 301 → admin。
- 证书用 `certbot certonly --webroot -w /var/www/html -d ...x4 --deploy-hook "systemctl reload nginx"`
  （全自动续签，不依赖 nginx 插件改配置）。
- 反代必须透传 `Host` + `X-Forwarded-Host`（否则租户解析失败）、WS 用 `$connection_upgrade` 映射、
  SSE 需 `proxy_buffering off`。

### 「在服务器上 git + docker build 会不会更快」的结论

用户提议改成服务器本地构建。评估结论：**长期不要这么做，但首次上线可以先这么做**。
- 服务器本地构建对 **bls-server 单服务**其实不慢（依赖层被缓存后增量重建 1-3 分钟），
  真正的杀手是 **bls-admin 前端构建**（`npm install` 1-2GB + max build，峰值内存 1.5-3GB，
  小规格 ECS 容易 OOM，且和 bls-server/mysql 共用同一个 dockerd，可能连带拖死）。
- 长期用 CI 构建的优势：服务器只 pull 几十 MB、有 `${CNB_COMMIT_SHORT}` 标签可回滚、
  构建前还跑 lint/test、不占生产资源。
- 用户想本地构建的真实原因很可能是**制品库里现在还没有镜像**（CI 从未成功跑过，
  而 `.ci/.build.yml` 的 `<< 'ENDSSH'` 引号 bug 会让它必然失败）。
- 给的做法：首次 `docker compose --env-file .env.docker build bls-server` +
  `up -d --no-deps bls-server`（**不带 `-f docker-compose.deploy.yml`**，这样才用本地 build 的镜像
  而不是去 registry 拉），链路跑通后再修 CI 切回 pull 模式。

补充结论（修正上一节的"长期不要本地构建"）：
- 端到端墙钟时间上，**服务器本地构建其实可以和 CI 路线相当**（CI 路线要付"git push + CI 排队/构建"，
  服务器路线只付"git pull + build"）；CI 路线的真正优势是**不占用生产机资源 + 有带 tag 的镜像可回滚
  + 构建前跑 lint/test**，而不是"更快"。
- 三条机器要分清：① 用户的阿里云 ECS（跑容器）② CI 构建机 ③ 镜像仓库。走 CNB 时 ②③ 都是腾讯的。

  带 = 去 registry 拉；不带 = 用本地 build 的镜像。

  作为制品库，构建放哪都行。

这个方案**成立**，优点正是"生产机不参与构建"（把最吃资源的前端构建放本地）。落地要点：
- 本地必须指定 `--platform linux/amd64`（Windows 默认也是 amd64，但显式写更稳）。
- 镜像 tag 必须是 compose 默认名 `bls-kox-bls-server`（project 名来自 `docker-compose.yml` 的
  `name: bls-kox`），否则 `up -d` 找不到镜像会触发重新 build；同时再打一个 commit tag 用于回滚。
- **Windows PowerShell 5.1 别用 `docker save | gzip` 管道**（文本管道会损坏二进制）：
  先 `docker save -o` 落盘，再用 `tar -czf` / 7-Zip 压缩；`docker load -i` 支持 gzip。
- 唯一实质代价：无层去重 → 每次**全量传输**（bls-server 镜像约 400MB 未压缩 / 约 150MB 压缩），
  受本地上行带宽限制。
- 必须把镜像 + `docker-compose.yml` + `.env.docker` 按**同一个 commit** 一起更新，避免错配。
- 若要保留"增量传输 + tag 回滚"又不引入腾讯，建议用**自己的阿里云 ACR**（个人版免费、同地域）。
